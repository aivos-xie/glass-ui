# 设计决策与材质层级

[简体中文](design-system.md) | [English](../docs/en/design-system.md)

用于整页改造、复杂组件组合或“更像液态玻璃”的请求。单个控件不需要先写一份完整设计方案。

## 先确定玻璃承担什么作用

从当前项目提取品牌色、字体、间距、圆角、组件行为和支持平台。保留这些约束，再决定材质；用户未要求时不更换字体、图标体系或信息架构。参考截图只用于分析视觉关系。

| 页面层 | 默认处理 | 适合玻璃的情况 |
| --- | --- | --- |
| 内容：正文、表格、图表、照片 | 优先保持清晰和真实颜色 | 用户明确要求，且有稳定可读底色 |
| 结构：分区、布局、容器 | 间距、排版、细边界 | 容器需要透出上下文，而不是单纯增加装饰 |
| 操作：导航、搜索、工具栏、浮层 | 适合使用统一玻璃材质 | 需要浮在内容之上、保持上下文或表达临时状态 |

每个玻璃区域应能解释其用途，例如“导航在滚动内容之上”“选中指示器与轨道分层”。不把“所有卡片都透明”当作统一设计的必要条件；也不因此拒绝用户明确要玻璃卡片的要求。

## 材质强度独立于颜色主题

先选轻、常规、厚三档功能强度，再选磨砂、清透、染色或窄棱镜外观。

- 轻：小控件和选中指示器，低 blur、细边缘、浅投影；透明程度受文字可读性约束。
- 常规：工具栏、信息卡、导航；稳定底色加柔和阴影。沿用项目默认圆角。
- 厚：菜单、对话框、密集文字浮层；提高不透明度和层次，避免用更大 blur 代替可读底色。

一个视图默认用少数一致档位。嵌套层级优先用描边、纯色或透明底区分，避免每层都单独模糊。数值起点见[材质与交互](materials-and-motion.md)，实际 CSS tokens 在 `assets/demo/glass.css`。

## 品牌、排版与状态

主品牌色首先用于主操作、选中和焦点；危险、成功仍保留各自语义色。不要把系统玻璃风格等同于复制 Apple 的图标、版式或文案。小文字和长标签不因“轻盈”而降低对比或缩小字号。中英文、两行标签、200% 缩放都要检查，标签文字不能随胶囊变形。

在实际背景的最亮、最暗、复杂区域与滚动状态分别检查对比。优先依次增加表面不透明度、调整文字颜色、降低背景复杂度；阴影和光晕不是可读性证明。内容区通常不需要折射，控件需要的折射也应集中在边缘。

## 让玻璃材质清楚可见

独立展示页或用户明确要求增强玻璃感、且没有既定主题时，可先用深色底配冷暖相邻的静态背景形状。已有品牌或浅色业务界面继续沿用当前主题，通过透明填充、细高光和可见背景建立材质，不为套用样板强行改暗。

先确认目标组件背后确实有明暗或色彩变化，再调 alpha 与 blur。长页面可用固定静态背景或各区域自己的底景；新增内容、切换面板和真实滚动后都要复查，避免背景只覆盖首屏。装饰保持在内容后面，不拦截点击，也不靠持续动画证明玻璃感。

导航的轨道、选中胶囊和前景文字分层处理：轨道轻磨砂，胶囊更薄、更透，文字保持不透明。边缘用有方向的窄高光与轻下沿阴影表达厚度；不要把轨道、胶囊与内部按钮都做成同样浓的白色填充。具体起点与回退见[材质与交互](materials-and-motion.md)。

## 交付时记录有用决策

按任务规模写清材质用途、所用 tokens、渲染路线、降级方式和测试环境。用户要求直接实现时，先做必要检查再实施，不强制增加审批步骤。不要借材质改造删除、合并或重排无关功能。
